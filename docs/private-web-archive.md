# Private website and forum archive

The static viewer is generated by `tools/restore_web_archive.py`. Raw Wayback
responses, the resumable recovery ledger, build files, and measurements stay
under ignored `wb/site-archive/`. The deployable folder is
`wb/site-archive/build/`; game clients and research evidence are not deployed.

The source URL inventories were recovered from Wayback CDX on 21 October 2026:

- `work/wayback-site-index.json`: aceofangels.com, including subdomains.
- `work/wayback-forum-index.json`: flyingrockllc.com, including subdomains.

Each query uses `output=json`, `filter=statuscode:200`, `collapse=urlkey`, and
`fl=timestamp,original,mimetype,statuscode,digest,length`. These inventories are
discovery evidence, not proof that every response body remains retrievable.
Documented snapshot URLs in `docs/history/2026-10-20-research-handoff.txt` seed the crawl.
Recovery is limited to captures through 2011. Later indexed captures include
a reset WordPress installation and domain-parking redirects, rather than the
original game website.

```powershell
# Initial import and recovery; later invocations resume the ledger.
.venv/Scripts/python.exe -I tools/restore_web_archive.py --import-indexes --recover --limit 5000

# Compare additional original-forum captures and recover the larger versions.
.venv/Scripts/python.exe -I tools/restore_web_archive.py --import-forum-versions --recover --limit 5000

# Build from already recovered bytes without further archive requests.
.venv/Scripts/python.exe -I tools/restore_web_archive.py
```

Requests are sequential and paced, with backoff for throttling or service
failures. Creating `wb/site-archive/STOP` stops after the current request.
Remove it to resume. Do not run multiple recovery/build processes against the
same ledger. `--retry-missing` explicitly retries unavailable responses.

The viewer preserves the downloaded page body, styling, images, and frames
where available. Named-frame targets and base-URL resolution are retained;
the capture banner stays out of very short navigation frames. The HTML parser
is explicitly finalized so malformed legacy character references do not
silently truncate long scoreboards or other pages. Original scripts, form
actions, event handlers, and automatic
redirects are removed. Login, posting, moderation, executable, and game-download
URLs are excluded. Links and CSS image URLs resolve to local recovered files
or an unavailable notice. Original Wayback source links are retained in the
page banner. The index searches recovered titles and URLs; it does not claim
to provide full-text search. Capture dates vary across the collection.

For the original UBB threads, `work/wayback-forum-versions.json` contains a
second CDX query over `www.flyingrockllc.com/ubb/Forum` with prefix matching,
successful HTML responses through 2011, and digest collapsing. It returned
1,020 capture records covering 848 original URL strings. Selection prefers the
largest indexed compressed response, then the later date on ties. This is a
practical way to favor fuller thread bodies, not proof that every historical
reply survived. A previous recovered body remains the fallback if an upgrade
cannot be retrieved. The initial comparison queued 36 larger versions.

The two large wrapped `players/scores/by_names.html` captures are approximately
14 MB each. Their HTML-specific recovery allowance is 64 MiB; other individual
captures retain the 12 MiB limit. Game installers and binary downloads remain
excluded. Headline extraction uses the article heading rather than the older
navigation label "Main Menu".

Newly discovered links absent from the complete successful-URL inventories
are recorded as unavailable instead of repeatedly requesting uncaptured
forum pagination and controls. Explicit documented capture seeds can still
be fetched directly. Later `--import-indexes` runs can add newly available
inventory records; raw responses already recovered are retained.

`ledger.json` records the original URL, returned replay URL, capture timestamp,
SHA-256, size, content type, and recovery state. `summary.json` measures the
generated deployment separately from raw downloaded bytes. Missing images,
uncaptured documents, and pending recoveries must not be presented as complete.

## Hosting boundary

The archive is a copy of third-party pages, so it is deployed privately, not
published. The maintainer's copy is a dedicated Vercel project created with
`publicSource: false` and `ssoProtection: {"deploymentType":"all"}` before
uploading content. Keep protection enabled on every deployment and alias.
No public object-storage bucket, shareable bypass link, or custom login is
needed. Robots directives supplement authentication; they do not replace it.

Before each release, inspect the project identity and protection settings.
Afterward, confirm the deployment is READY, inspect its aliases, and check
anonymous requests to the index, catalog, archived pages, and direct images.
Check authorized content with `vercel curl`, without exposing authentication
headers or tokens in reports.
