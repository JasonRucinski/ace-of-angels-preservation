ACE OF ANGELS — RESEARCH AND TECHNICAL HANDOFF FOR CLAUDE CODE
Research checked: 20 October 2026

PURPOSE

Continue the preservation and multiplayer-server investigation for Ace of Angels,
the late-1990s/early-2000s 3D space combat game by Flying Rock Enterprises (FRE).
The user first requested a working game download, the developers' complete
fictional universe, and evidence of a revival. The work then expanded to deeper
archive searches, additional releases, and possible multiplayer host files.

This document contains the verified results, exact retrieval links and hashes,
static binary findings, source links, archive coverage, and unresolved leads.
It is a handoff of completed research, not a claim that multiplayer now works.

The original research files were in another ChatGPT environment. Claude Code
will NOT automatically have those files. Download the public originals using
the manifest below, or ask the user for any files they have retained. Temporary
paths in the final evidence section are provenance references only.

1. CURRENT STATE — READ THIS FIRST

• Five complete installers were recovered and inspected: runtime versions
  2.0.0, 2.7.1, 2.8.0, 2.8.2, and 2.9.2. A sixth recovered binary is a standalone
  replacement client, version 2.3.1, without its complete installation assets.
• All five installers can be read as ZIP/self-extracting archives using Python's
  zipfile module without executing the Windows installer.
• The latest recovered package has installer resource version 2.11.1.0, but its
  embedded game client reports 2.9.2 through its compiled version variables.
  Do not rename the actual game version 2.11.1 without explaining this conflict.
• No identifiable dedicated server executable, released server source, account
  database, or server-state dump was recovered. All five complete installers
  were inventoried, including checks for PE executables under unusual names.
• Clients contain valuable network names, default ports, packet-size diagnostics,
  source-path clues, and packed game data. None of these alone is a working host.
• The original universe is the Known Sphere. Forgotten Suns is a separate
  backstory for the later MMO redesign. The official site explains the change.
• There was a documented OGRE-based restart in 2009–2010. A separate July 2020
  YouTube announcement by an account identifying itself as original developer
  Curtis Hartung describes rebuilding the game with Unreal Engine 4.
• No current 2026 development activity, public UE4 build, or working revived
  multiplayer service was confirmed. The 2020 announcement is real evidence of
  intent at that time, not proof that the project is active today.
• Facebook chatter was part of the user's recollection, but no concrete Facebook
  revival post or comment permalink was verified. Do not invent one.
• No installer or game EXE was executed during this work. Gameplay, authentication,
  connection behavior, and server compatibility have not been tested.

Evidence wording used below:
CONFIRMED = retrieved bytes, static inspection, or content actually read.
REPORTED = a source states it, but the underlying event was not independently tested.
INFERENCE = a conclusion suggested by evidence, with limits stated.
LEAD = a possible next source, not a recovered or verified deliverable.

3.1 How the actual versions were established

The clients contain the format string “Ace of Angels (v%d.%d.%d Beta)”. Static
cross-references show the three globals passed to that title/log formatting call.
The file-backed values and relevant zero-initialized virtual data were checked.

Version | Major/minor/patch locations
2.0.0 | major file 0x120D4C, VA 0x520D4C = 2; minor VA 0x52F038 and patch VA 0x52F03C are zero-initialized virtual data, with no corresponding file bytes.
2.3.1 | file 0x19A370 / 0x19A374 / 0x19A378 = 2 / 3 / 1.
2.7.1 | file 0x2838B8 / 0x2838BC / 0x2838C0 = 2 / 7 / 1.
2.8.0 | file 0x1D16DC = 2; file 0x1D16E0 = 8; patch VA 0x5E3B40 is zero-initialized virtual .data, with no corresponding file bytes.
2.8.2 | file 0x1D1ECC / 0x1D1ED0 / 0x1D1ED4 = 2 / 8 / 2.
2.9.2 | file 0x1D1A10 / 0x1D1A14 / 0x1D1A18 = 2 / 9 / 2.

Additional reference points:
• 2.0.0 format string VA 0x51C134; nine code references per version global were reads.
• 2.3.1 format string file offset 0x1917B0.
• 2.8.0 format string file offset 0x1C2464; five format references and twelve
  references per version global, all reads in the inspected code.
• 2.7.1, 2.8.2, and 2.9.2 each had five references to the version format.

Map file offsets, RVAs, and VAs through the PE section table. Do not blindly add
0x400000 to every file offset. Virtual zero-fill matters for 2.0.0 and 2.8.0.

Misleading labels already encountered:
• Installer resources in the 2.7.1, 2.8.0, and 2.8.2 packages say 2.2.0.0.
• Old notes say 1.7.5 or 2.3.0; some UI resources say 2.5.4.
• Installer-stub PE timestamps from 1997/2000 are not client build dates.
• The Family GamePack installer resource says 2.11.1.0, while its client is 2.9.2.

4. MULTIPLAYER HOST / SERVER FINDINGS

4.1 What was and was not present

All five complete installers were inspected. Member counts were 17, 38, 40, 40,
and 41 for 2.0.0, 2.7.1, 2.8.0, 2.8.2, and 2.9.2 respectively. Appendix C records
their full member inventories so the result is reviewable.

No separate multiplayer host executable, server source tree, player-account
database, or server-state dump was identified. This finding is limited to the
material inspected. It does not prove that the developers never distributed a
server, or that an undocumented hosting path cannot exist inside a client.

The earliest package contains the game client and RENEXE.EXE. Later packages
contain these executable/helper names:
AOACLIENT.EXE; RENEXE.EXE; OCXREG32.EXE; REGSVR32.EXE; UNWISE32.EXE.
Other PE components include PROGRESS.DLL, WISE0001.DLL, W32INST.DLL, ACTIVESKIN.OCX.

The helper material relates to update/rename, component registration, and
uninstallation. RENEXE refers to AoAClient.exe/AoAClient.ex_ and ActiveSkin
registration. COM's DllRegisterServer export is not a multiplayer-host feature.
Every extracted member was checked for an MZ signature, including files without
an executable extension. No extra PE hidden under a data extension was found.

4.3 Network defaults — exact 2.7.1 client offsets

Records consist of a 64-byte ASCII name followed by a four-byte IEEE-754 float.

Name | Name file offset | Value file offset | Default float
GAMESERVERPORT | 0x28C3D4 | 0x28C414 | 5031.0
NAMESERVERPORT | 0x28C418 | 0x28C458 | 5032.0
STATION_RUNONPORT | 0x28C4E4 | 0x28C524 | 5033.0
STATION_TCPJOBPORT | 0x28C528 | 0x28C568 | 5034.0

LOCALPORT and SERVERPORT also have default 5033 in the inspected records.
Related defaults recur in other clients. The 2.0.0 records use 32-byte names,
so do not use the later record stride when parsing that version.
Historical hostname found in the clients: aoahost.com.

These are compiled defaults, not independently documented firewall instructions.
Transport, direction, service ownership, and current endpoints remain to be
established from code or controlled testing. Do not present an open port or a
working server as a confirmed finding.

4.4 Packet-size diagnostics — exact 2.7.1 evidence

Structure label | Logged value | Push instruction VA | Format-string VA
SPacketServerRegister | 61 / 0x3D | 0x476AFE | 0x675DD8
SPacketRequestServerConnect | 35 / 0x23 | 0x476A95 | 0x675EC0
SPacketGameserverList | 461 / 0x1CD | 0x47708B | 0x6754C8
SPacketGameserverConnectStatus | 5 | 0x476B42 | 0x675D5C

These calls use a common logging function at VA 0x60B0C0 and logging object at
0x6A58B8. A related SGameserverList diagnostic is 46; 461 = 1 + 10 × 46 supports
the interpretation as compiled structure sizes. There is no literal sizeof
label, but the call sites and constants are strong size evidence.

Do NOT treat 61, 35, 461, and 5 as confirmed packet opcode IDs. Neither exact
wire lengths nor field layouts, framing, byte order, handshakes, encryption,
compression, or a compatible implementation have been established.

Other useful names and debug source-path clues:
CClientComm; CAOAComm; CStationServer.
AoA_Client_Comm.cpp; AoA_LoginDlg.cpp; AoA_StationDlg.cpp; AoA_World.cpp;
PlayerLoginInfo.cpp; AoA_MissionData.cpp.
AoAClientCode; AoAIncludeCode; AoADBaseCode; AoAAICode.
These are strings/debug paths in compiled binaries, not recovered source files.

10. NEXT WORK FOR CLAUDE CODE

The most useful next step is a reproducible static analysis of the original
network client, using 2.7.1 as the reference and 2.9.2 for comparison. Repeating
broad searches should have a specific new archive, filename, or code clue.

Suggested sequence:

1) Download the original 2.7.1 installer and the Family GamePack installer using
   Appendix A. Verify SHA-256 and preserve immutable originals with unique names.
   Optionally retrieve the other versions for code/data comparisons.
2) Read their ZIP directories and extract only selected members at first. Do not
   run the installer merely to unpack it. Keep each build in a separate folder.
3) Reproduce the client identity, version variables, network records, and packet
   diagnostic call sites listed above. Record tool versions and exact addresses.
4) Trace login, name-server, Station, and game-server connection paths. Find
   serializers, dispatch tables, message IDs, framing, lengths, transport setup,
   disconnect handling, and any version negotiation. Separate evidence from
   hypotheses in the resulting protocol notes.
5) Compare offline world initialization with online entry and simulation paths.
   Determine whether substantial authoritative simulation exists in the client,
   and whether a real reachable hosting mode exists. Shared strings are not enough.
6) Trace readers for AOAOBJECTS.ODB, SCRIPTS.AOA, SCENARIOS.AOA, SCRTY.BIN, and
   related files. Check the ResHax sample-folder lead if it adds useful material.
7) Produce a protocol specification and missing-component list before claiming
   that a minimal server can be implemented. A login emulator, Station service,
   and authoritative game simulation may be different amounts of work.
8) If runtime analysis becomes necessary, use an isolated local environment with
   controlled endpoints. Do not send traffic to historical IPs by default.
9) Revisit original developer backups/source as a lead only with concrete evidence.
   No one has confirmed possession of a surviving server copy. Ask the user
   before sending any outside messages.

No server emulator, source patch, asset extractor, or working multiplayer setup
was produced during this research.

11. SMALL REPRODUCTION EXAMPLES

A standard-library inspection snippet, after downloading a file locally:

    from pathlib import Path
    import hashlib, zipfile

    path = Path("aoa_2.7.1_full.exe")
    print(path.stat().st_size)
    print(hashlib.sha256(path.read_bytes()).hexdigest())
    with zipfile.ZipFile(path) as archive:
        for member in archive.infolist():
            print(member.filename, member.file_size, f"{member.CRC:08x}")
        names = [n for n in archive.namelist()
                 if n.replace("\\", "/").split("/")[-1].lower() == "aoaclient.exe"]
        assert len(names) == 1
        Path("aoaclient_2.7.1.exe").write_bytes(archive.read(names[0]))

That writes a chosen output filename rather than trusting an archive member path.

reader, then apply the same ZIP inspection to its inner EXE.
